## Rutas canónicas del módulo

- `GET /presupuestos/{id}/cronograma` y `POST /presupuestos/{id}/cronograma`:
  lectura y alta 1:1.
- `PUT /cronogramas/{id}/configuracion`: reemplazo de configuración con la
  política canónica de pérdida.
- `PATCH /cronogramas/{id}/actividades/{aid}`: comandos de programación y avance.
- `GET /cronogramas/{id}/vistas`: proyección común de Gantt, valorizado y curva S.
- `POST /cronogramas/{id}/revisado`: captura del snapshot de revisión.

No se crean aliases de configuración, vistas ni comandos fuera de estas rutas.

## Invariantes que todos los planes deben preservar

| Invariante | Regla operativa |
|---|---|
| Agregado | Cada versión de `Presupuesto` tiene cero o un `Cronograma`; la unicidad 1:1 la protege la BD y la operación de alta usa bloqueo para evitar carreras. |
| Cobertura | Cada `Rubro` de la versión tiene exactamente una `Actividad` cuando existe cronograma; no hay alta, edición ni borrado manual de actividades. |
| Sincronía | Agregar/eliminar un rubro sincroniza su actividad dentro de la misma transacción del write-through de `recalculo`; una actividad huérfana no se conserva. |
| Identidad | `id` en HTTP/JSON es UUIDv7; `BIGINT` es exclusivamente interno. UUID malformado o no-v7 → 400 `validacion`; recurso inexistente o ajeno → 404 `no-encontrado`. |
| Autorización | Roles `USUARIO` y `SUPER_ADMIN`; un usuario no puede inferir la existencia de un proyecto, presupuesto, cronograma o actividad ajena: se responde 404. |
| Precisión | Dinero persistido en `NUMERIC(14,6)` y transportado como string decimal; porcentajes y avances se transportan/persisten con escala 4. Nunca `double`, `float`, `parseFloat` ni `toFixed` para dominio. |
| Períodos | Las claves son strings de enteros 1-based, dentro de `1..numeroPeriodos`; un mapa completo se reemplaza atómicamente. |
| Distribución | Cada actividad completa cumple `Σ avances = pesoPonderado` exactamente a escala 4 y `desviacion = 0.0000`; el cronograma completo además termina en `100.0000`. Una distribución incompleta se guarda como `BORRADOR`; la desviación se muestra y no bloquea la edición. |
| Desactualización | Un marcador/snapshot canónico debe detectar cambios relevantes del presupuesto, incluso cambios compensados que conserven el total general. La alerta informa y ofrece marcar como revisado, pero nunca bloquea la exportación por sí sola. |
| Exportación | La generación es server-side y usa una proyección común para xlsx/pdf. Los campos SERCOP se trazan al catálogo oficial de Licitación y al Formulario LICO 2023-001 §1.8; MSPDI es XML estándar `application/xml`, requiere `Proyecto.fechaInicio` y nunca es `.mpp`. |
| Motor | No se modifica `motor/` en estos planes. Si el contrato exige tocar `Motor`, `Consolidador` o sus records, se detiene el plan y se abre un plan/guard explícito. |

## Alcance del módulo

### Incluye

- Configurar `unidadTiempo` (`SEMANA` o `MES`) y `numeroPeriodos` positivo.
- Crear y leer el cronograma de una versión de presupuesto.
- Importar automáticamente una actividad por rubro y mantener la cobertura 1:1.
- Seleccionar períodos activos, generar distribución uniforme, editar el mapa de
  avance y reportar `desviacion`.
- Derivar segmentos contiguos para tabla, Gantt y export, sin convertirlos en
  una segunda fuente de verdad.
- Exponer total por período, acumulado, pesos con escala 4, estado de
  distribución y alerta de desactualización.
- Exportar el documento de cronograma cuando los gates formal y cuantitativo
  estén satisfechos.

### No incluye

- CPM, ruta crítica, predecesoras, holguras, hitos, calendarios laborales,
  fechas de inicio/fin, colores o subpresupuestos del proyecto de referencia.
- CRUD de actividades desligadas de `Rubro`.
- Cambios a `motor/`, V001–V008, `thesis-docs` durante esta sesión, frontend,
  migraciones reales, pruebas, Bruno, scripts, índices o artefactos SDD/OpenSpec.
- Escritura de `.mpp` propietario. Si se autoriza interoperabilidad, el formato
  es un writer MSPDI XML independiente y explícito.

## STOP register

- **STOP-026-DOC:** no se puede iniciar backend mientras los documentos canónicos
  no expresen la misma identidad, paths, shape y fórmulas. No se resuelve con
  un DTO de compatibilidad que acepte IDs numéricos.
- **STOP-027-ID:** si la función `uuidv7()` o el trigger común no están
  disponibles, o si el número de migración no puede determinarse de forma
  segura después de V008, se detiene la migración; no se modifica V001.
- **STOP-028-LOSS:** si el body del 409 no puede enumerar de forma determinista
  los valores que se perderán, no se habilita la reducción silenciosa.
- **STOP-029-SEMANTICS:** si el gate no decide si `segmentos` es derivado y no
  fija el algoritmo que produce `100.0000`, no se implementa distribución.
- **STOP-030-STALE:** si el mecanismo de revisión solo compara el total general y
  no detecta cambios compensados que alteran pesos, se detiene I-09 antes de código.
- **STOP-MOTOR:** si la solución requiere modificar `Motor`, `Consolidador` o
  records del paquete `motor`, se detiene y se solicita un plan específico; no
  se copia la fórmula en un segundo calculador sin guard.
- **STOP-031-SERCOP (resuelto en 026):** se localizó el Formulario LICO oficial.
  Si esa procedencia deja de ser verificable o se pretende afirmar un layout no
  sustentado, reactivar el STOP; PDF/maqueta/`ingepresupuestos` solos no bastan.
- **STOP-031-GM:** si la suite GM completa no cumple el criterio de aceptación
  vigente —incluidos los residuales ya documentados y su tratamiento aprobado—
  no se comienza el writer.
